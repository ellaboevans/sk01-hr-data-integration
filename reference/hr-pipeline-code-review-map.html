config.py — pipeline contract and constants

Paths

PROJECT_ROOT and data directories

Derive all locations from the module file instead of the shell's current directory. This makes module execution reproducible.

Inputs

RAW_FILES / REFERENCE_FILES

Central registries used by orchestration. Adding a source requires both configuration and dispatch logic in ingest.py.

Rules

Exchange rates and prefixes

Fixed USD rates make output deterministic. COMPANY_PREFIXES and SOURCE_PRIORITY are declared but not used by the current implementation.

Schema

STANDARD_EMPLOYEE_COLUMNS

The canonical 23-column interchange schema. Alignment functions add missing fields as null and reorder every source consistently.

ingest.py — load formats, then align schemas

Function Step-by-step behavior Review note
_handle_missing_file Logs an error and returns an empty DataFrame. Empty inputs now align to an empty canonical frame instead of raising KeyError. A source-level completeness gate is still needed to prevent publishing an unexpectedly partial employee population.
_ensure_standard_columns Copies input → adds every absent canonical column as pd.NA → returns columns in canonical order. Good boundary between source-specific and shared transformations.
_extract_nested_value If a JSON cell is a dict, return its requested key; otherwise return missing. Prevents malformed nested fields from crashing individual extraction.
ingest_globaltech_hris Existence check → UTF-8 read_csv → attach provenance → log count. Broad exception handling converts all failures to an empty frame, potentially masking a failed critical identity source.
ingest_acquiredco_hris Load JSON → accept dict/list → pull employees → slice into 500-record pages → concatenate pages → tag source. Pagination is simulated in memory, not API pagination; page_size <= 0 is not guarded.
ingest_payroll Read Excel with pandas → attach payroll provenance. Required payroll columns are checked by align_all_sources before this adapter runs.
ingest_benefits Parse XML → find every enrollment node → turn its direct children into a dict → DataFrame. Simple and clear; assumes flat children and ignores repeated child tags/attributes.
ingest_all_sources Iterate configured sources → string-based dispatch → collect frames → log row/column summaries. A registry of callables would scale better than an if/elif chain.
align_*_schema Create a fresh frame → rename/derive source fields → hardcode company/source metadata → enforce canonical columns. Benefits are always labeled GlobalTech. Confirm that the XML cannot contain AcquiredCo employees.
align_all_sources Convert empty inputs to canonical empty frames → validate required raw columns → dispatch each nonempty frame to its alignment adapter → log dimensions. Missing columns now raise source-specific ValueError messages. Nested JSON shapes and source data types remain follow-up contract checks.

clean.py — normalize values and business taxonomies

normalize_name

Null guard → Unicode NFKC normalization → trim → title case. This reduces superficial formatting differences.

Challenge: title casing can alter valid names such as “McDONALD” or “van der Waals.”

normalize_employee_id

Select GT/AC namespace → parse numeric IDs or first digit run → format six digits. It prevents cross-company ID collisions.

Challenge: it accepts zero and silently discards nonnumeric ID structure.

normalize_manager_id

Reuse employee-ID normalization so foreign keys use the same canonical format.

normalize_employment_type

Map known spelling/abbreviation variants into three allowed categories; unknown values become null and are logged.

standardize_date

Parse in UTC → remove timezone → reject before 1970 or after today.

Challenge: cleaning accepts dates from 1970, while golden-dataset validation later requires 1990 or newer.

parse_salary

Remove common currency symbols and commas, then cast to float. Missing/unparsable values stay missing.

normalize_salary_to_usd_annual

Parse amount → fixed currency conversion → multiply by annual/monthly/biweekly factor → round.

High-risk assumption: frequency tells how often the provided amount is paid. Existing 3,004 failures suggest some “Bi-Weekly” values may already be annual salary.

clean_standardized_dataframe

Copies the aligned frame → normalizes names/email/IDs/types/dates/salary → applies department reference mapping.

Fallback: derives full_name from first/last when available and preserves the normalized source-provided full name when both components are missing.

load_department_mapping

Load CSV → require three columns → return an empty correctly shaped mapping only when file is missing.

Challenge: other read/parser errors propagate; decide whether that fail-fast behavior is intentional.

map_departments

Build case-insensitive lookup keyed by (source_system, source_department) → map row-by-row → collect and log unique misses.

dedup.py — identity spine, enrichment, and candidate matching

Function What it guarantees Important detail
combine_cleaned_sources One long canonical table. concat preserves all source rows; it does not match anyone yet.
build_source_systems Stable, sorted, pipe-delimited provenance. Example: benefits|globaltech_hris|payroll.
deduplicate_hris_identity_records One HRIS survivor per canonical ID plus a full duplicate review table. Ranks by non-null identity count, source name, and stable source row order. A unique internal row marker ensures exactly one duplicate is marked kept_in_golden=True, even when two source rows are otherwise identical.
summarize_payroll_records At most one payroll record per employee. Latest effective date wins; ties depend on stable input order and are not explicitly resolved.
summarize_benefits_records At most one benefits summary per employee. Any record means enrolled; earliest enrollment date wins.
summarize_source_systems One provenance summary per employee ID. Uses all combined records, including unmatched enrichment; only matched IDs reach golden.
build_exact_id_golden_dataset HRIS-only identity spine, exact-ID enrichment, ghost isolation, and unique golden ID. Drops enrichment placeholders from HRIS → deduplicates HRIS → splits matched/ghost enrichment → summarizes → left-joins → defaults benefits false → asserts uniqueness.
find_duplicate_employee_ids Postcondition check that golden IDs are unique. Expected output is empty because the builder already raises on duplicates.
find_duplicate_emails Only duplicate emails spanning both companies. Same-company reuse is intentionally ignored.
find_same_name_cross_company_matches Review pairs with identical normalized full name and hire dates ≤30 days apart. No merge occurs; it emits evidence for HR.
find_fuzzy_name_hire_date_matches Review pairs scoring ≥88 using word-order-insensitive name similarity within the 30-day date block. Date blocking avoids a full 3,001 × 15,000 comparison, but iterrows is still slow at scale.
Why exact first, fuzzy second? Exact namespaced IDs are deterministic enough to automate. Names are ambiguous, so fuzzy scores supply candidates—not truth. The pipeline deliberately separates integration from entity-resolution review.

validate.py — declarative checks and a dataset-level gate

ValidationCheck stores a name, description, and function that returns one boolean per row. DataQualityValidator._build_checks defines 14 checks for keys, formats, required values, allowed categories, ranges, foreign keys, and booleans.

run

Execute each mask → treat null mask results as failure → count passed/failed → calculate rate → mark a check PASS only when zero rows fail.

assert_quality_gate

Fail immediately when a critical employee-ID or company-origin check fails. Otherwise count failed check types and raise when more than two noncritical checks fail.

get_failed_records

Rerun one named validation and return the failing rows with diagnostic columns.

Private validators

Hire date: 1990 through today. Salary: null or $20k–$2m. Manager: null or present in golden employee IDs.

Export methods

Write the summary as CSV/HTML and failed rows as CSV, creating directories as needed.

Gate semantics

Critical identity checks now fail immediately, but one noncritical check can still fail 3,004 rows and pass because only one check type failed. Ask whether risk tolerance should also cap row failure rates.

visualize.py — reporting layer

_add_source_note stamps provenance/time; _save_chart creates directories, tightens layout, saves at 300 DPI, closes the figure, and logs. Six plot functions compute an aggregate then render department headcount, country headcount, salary box plots, tenure histogram, department benefits rate, and validation pass/fail bars. generate_all_charts is the façade that invokes all six.

Review points: tenure uses the runtime date, so charts are not reproducible across days; boolean casting can turn some nonempty strings into True; empty salary/grouping inputs need explicit behavior tests.

pipeline.py — orchestration and publishing

  1. prepare_for_parquet_export coerces known columns to stable string, datetime, numeric, and boolean dtypes.
  2. build_probable_matches_export translates internal left/right fields to HR-facing names; exact-name pairs receive similarity 100; action is HR_REVIEW.
  3. main calls every stage in business order and prints summaries.
  4. Same-name and fuzzy candidates are concatenated; exact-name candidates win when the same pair is found twice.
  5. The 14 validations run, then the quality gate may stop publishing.
  6. A new Parquet dataset is written to a staging directory and then read back to verify its row count. Only then is it moved into place, with the previous dataset retained as a temporary rollback backup during publication.
  7. Review CSVs, validation outputs, and charts are produced.

Remaining production consideration: staged writing prevents a failed Parquet write from destroying the previous output, and restoration is attempted if the swap fails. A versioned dataset plus an atomic metadata/pointer switch would provide stronger concurrent-reader guarantees in production.

Strong review observations

Good: explicit source authority

The code prevents payroll-only or benefits-only records from silently becoming trusted employees.

Good: uncertainty stays visible

Fuzzy matches, ghosts, duplicates, and salary outliers are preserved as review artifacts rather than hidden.

Test coverage is foundational

The new suite covers core integration, empty/schema-drift inputs, duplicate survivor auditing, critical gates, match exports, and staged publishing. More normalization and visualization edge cases remain useful follow-up work.

Risk: source schema drift

Required raw columns are now validated with source-specific errors. Nested JSON shapes and source data types still need deeper contract validation.

Risk: PII in version control

Raw HR files, golden Parquet, exception CSVs, charts, and pipeline log are tracked by Git. If data is not explicitly synthetic, this is a serious privacy/governance issue.

Decision needed: zero-valued IDs

The discarded filter has been removed, but the canonical format still permits AC-000000. Confirm whether zero is a valid source identifier before rejecting it or adding a dedicated validation rule.

Documentation maintenance

Keep source filenames, validation-gate semantics, and publication behavior synchronized with the implementation. The schema table still contains unescaped pipes that should be cleaned up.

Maintainability

COMPANY_PREFIXES is now the source of truth for ID namespaces. SOURCE_PRIORITY remains unused and should either drive survivor ordering or be removed.

Questions a reviewer may ask—and compact answers

Question Answer you can give
Why not concatenate all sources and drop duplicates? Because source rows have different authority and grain. HRIS establishes identity; enrichment sources can contain multiple payroll or enrollment events and must be summarized first.
Why namespace IDs? Source IDs are only unique inside their company. Prefixing avoids a GlobalTech “1” colliding with an AcquiredCo “1.”
Why not merge score-100 name matches? Names are not identifiers. Two people can share a name and similar hire date, so the cost of a false merge justifies human review.
Why left joins? The identity spine must retain every trusted HRIS employee even when payroll or benefits enrichment is missing.
Why Parquet and partitioning? Parquet preserves typed columnar data and supports selective reads; company partitioning can prune reads for company-scoped analysis.
What would you productionize first? Tests and schema contracts; secure/untrack HR data; configurable governed reference tables; failure-rate gates; versioned publishing; orchestration and observability.
